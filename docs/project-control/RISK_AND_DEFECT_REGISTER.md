## 🔴 SIGNALS-6 (HIGH, research-integrity) — the factor-promotion pipeline promotes random JUNK

**Discovered 2026-06-26 by attempting the SIGNALS-1/2 fix (then reverted to stay green — see D-008).** When the `leakage_guard` brick-wall (SIGNALS-1) is removed, a **random junk factor is PROMOTED** by `promote_candidates`. Root cause: `research/alpha_factory.evaluate_factor` computes a **contemporaneous, market-timing** IC — `val_returns = returns_aligned.iloc[valid_idx].mean(axis=1)` (`alpha_factory.py:161-162`): the factor at `t` vs the **same-bar cross-sectional MEAN** return, with **no forward shift** and **no cross-sectional ranking across names**. So the only thing currently stopping junk promotion is the (broken) leakage wall that rejects *everything*.

**Implication:** SIGNALS-1, SIGNALS-2, SIGNALS-3, SIGNALS-4 are **ENTANGLED — they must be fixed as one unit**, not piecemeal:
1. `leakage_guard`: stop false-flagging normal label overlap (SIGNALS-1); keep genuine look-ahead + a real data-sufficiency check.
2. `PurgedWalkForwardSplitter._purge`: purge by **positional** bar distance (SIGNALS-2).
3. `evaluate_factor`: rebuild to a **cross-sectional forward-return IC** (factor ranks at `t` vs forward returns `t→t+h`, per name), fixing SIGNALS-3 (`factor_decay_profile`) and SIGNALS-4 (no-shift / market-timing).
4. **Acceptance tests (both required):** a random junk factor is REJECTED, and a constructed known-edge factor is ACCEPTED. Until both hold, the promotion pipeline cannot be trusted — and **golden rule 5** (no live promotion without validation) is only nominally satisfied.

**Severity:** HIGH/P0 for *research integrity* (the system could "validate" fake edges). **Not** a live-trading-safety issue today — the factor-promotion pipeline is not wired into the run-loop (nothing registers sleeve `ValidationResult`s online; see SIGNALS-5), so it cannot influence live orders yet. But it must be fixed before any factor research is trusted.

**Refined scope (2026-06-26, second investigation):** robust junk-rejection is NOT just a forward-shift. Evidence: the test fixture passes **raw** returns over only **120 obs / ~2 folds** (`tests/test_phase2.py:421-438`), and on such a tiny sample random junk can spuriously clear `selection_rule`'s loose thresholds even after a correct forward-shift. The fix therefore requires, together: (1) leakage_guard correctness, (2) positional purge, (3) `evaluate_factor` forward-return (ideally cross-sectional) IC, **and (4) the directive's §11 anti-overfitting machinery — a real Deflated Sharpe (trials-aware), PBO, and minimum-track-record/sample-size gate** to replace the current `*_proxy` placeholders. Acceptance: random junk REJECTED across *multiple seeds*, a constructed known-edge factor ACCEPTED, on an adequately-sized sample. **Effort: a dedicated focused effort (not a quick edit).** This is the keystone for all honest alpha work and the credible path to evaluating any >30% claim.
